# Perso — Agentic Development Guide

Perso is a self-hosted, open-source bento-grid personal dashboard. It is a
[Turborepo](https://turborepo.com) monorepo using npm workspaces (Node `>=20`).

```
perso/
├── apps/
│   ├── api/        # NestJS 11 backend (TypeScript)
│   └── web/        # React 19 + Vite 7 frontend (TypeScript, Tailwind v4, shadcn/ui)
├── packages/
│   └── shared/     # Shared types, widget contracts, utilities (@perso/shared)
├── turbo.json      # Turborepo pipeline
└── package.json    # Workspace root
```

## Golden Rules (read first)

1. **Lint after every change.** After writing or editing any code, run
   `npm run lint` from the repo root. Do not consider a task done until lint
   passes. Fix every error you introduce; do not leave new warnings behind.
2. **Do not write unit tests.** This project does not require unit tests — do
   not add `*.spec.ts` / `*.test.ts` files or test scaffolding unless explicitly
   asked. Quality is enforced through the linter and the type checker instead.
3. **TypeScript everywhere.** All code is TypeScript. Never introduce plain `.js`
   source files.
4. **Respect each workspace's own config.** ESLint, Prettier, and tsconfig
   differ between `web` and `api`. Match the conventions of the file you touch.
5. **Stay in scope.** Make atomic, focused changes. Do not refactor unrelated
   code or reformat files you are not changing.

## Commands

Run from the repo root; Turborepo fans out to each workspace and caches results.

```bash
npm run dev        # Run api + web in parallel
npm run lint       # Lint every workspace — run this after each change
npm run typecheck  # Type-check every workspace
npm run build      # Build every workspace
```

Scope a task to one workspace with `--filter`, e.g.
`npm run lint -- --filter=@perso/web`.

## Frontend rules (`apps/web`)

- **React 19, functional components only.** Use hooks; never class components.
  Extract reusable logic into custom hooks.
- **Path alias `@/`.** Import from `@/components`, `@/lib`, `@/hooks` — never
  long relative chains like `../../../lib/utils`.
- **Styling is Tailwind CSS v4.** Use utility classes. Merge/compose classes
  with the `cn()` helper from `@/lib/utils`. Use `cva` for variant-based
  components. Do not introduce CSS-in-JS or separate stylesheets.
- **shadcn/ui lives in `src/components/ui/`.** These files are vendored and
  regenerated by the shadcn CLI — do not hand-edit them. Add new primitives via
  the CLI; build app components on top of them elsewhere.
- **Icons** come from `lucide-react`.
- **Prettier (web):** no semicolons, double quotes, 2-space indent, `es5`
  trailing commas, 80 print width. Let Prettier format; do not fight it.
- **Accessibility & semantics:** prefer semantic HTML, keep `aria-*` and
  keyboard interactions intact, and never strip focus styles.

## Backend rules (`apps/api`)

- **NestJS 11 architecture.** Organize features as modules; use controllers for
  routing and services for business logic. Keep controllers thin.
- **Dependency injection.** Inject dependencies via the constructor with
  `private readonly`; do not instantiate services manually.
- **Decorators & DTOs.** Use Nest decorators (`@Controller`, `@Get`,
  `@Injectable`, …). Validate and type request payloads with DTO classes.
- **DTOs stay in `apps/api`.** Define the request/response *shapes* in
  `@perso/shared`; implement validation with Nest DTO classes in the API.
- **Async correctness.** Always `await` or explicitly `void` promises — the
  `@typescript-eslint/no-floating-promises` rule will flag unhandled ones.
- **Prettier (api):** single quotes, semicolons, `all` trailing commas. This
  differs from the web app — follow the API config here.

## Shared package (`packages/shared`)

Put **API contract types** (request/response shapes), **domain enums**,
**widget config contracts**, and **utilities** used by both `api` and `web`
in `@perso/shared`. Import via the package name, not relative paths.

- **Do put here:** `WidgetType`, `CreateWidgetRequest`, `WidgetResponse`,
  per-widget config interfaces, shared constants.
- **Do not put here:** NestJS DTO classes, TypeORM entities, React components,
  or anything with framework-specific decorators.
- **API DTOs** live in `apps/api` and should mirror the shared contract types.
  **Web** imports the shared types for type-safe API calls and widget rendering.
- `shared` must build before its consumers; no circular dependencies back into
  `api` or `web`.

## Commits

- **Conventional Commits.** Format: `type: description` using
  `feat | fix | docs | style | refactor | perf | test | build | ci | chore`.
- **One sentence.** The commit subject is a single, concise sentence in the
  imperative mood, lower case, no trailing period.
- **Atomic commits.** Each commit is one logical change. Do not bundle unrelated
  edits; split them into separate commits.

```
feat: add weather widget to the bento grid
fix: prevent dashboard crash when a widget has no data
refactor: extract grid layout logic into a custom hook
```

- Only commit when explicitly asked. Before committing, ensure `npm run lint`
  passes.
